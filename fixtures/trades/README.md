# fixtures/trades

Anonymised copy of the example TOS trades folder, generated by
`scripts/anonymize_statements.py` from the real (never-committed)
`~/workspace/example_trades/Trades/` folder. Used by the tests (and by the
e2e suite via `serve --demo --root fixtures/trades`); `wingspan serve --demo`
itself shows the wholly synthetic book in `../demo` instead.

What was anonymised, and what was deliberately left alone:

- **Trade files** (`Open Trades/`, `Closed Trades/`): copied byte-verbatim
  apart from execution-ref renumbering (below). They never contain the
  account number or any dollar balances.
- **Statement CSVs** (`Daily Trade Statement/`): the file *format* (UTF-8
  BOM, CRLF line endings, quoting style, section order, and every dialect
  oddity - the stray "Total Cash" row, the single-space line, `="..."`
  Excel refs, etc.) is preserved exactly.
  - The real account number is replaced by `00000000TEST` everywhere.
  - The broker's 13-digit execution reference numbers (`REF #` cells,
    `RE #` cross-references, `# ref=` hints in trade files) are renumbered
    into a synthetic ascending sequence starting at `9000000000001`, in
    chronological (numeric) order, with one map applied to every file so
    cross-references stay consistent. The sequence depends on which
    statements are present: adding a day renumbers everything after it,
    and the insta snapshots in `crates/wingspan-core/tests/snapshots` must
    then be re-accepted.
  - Every OPTION-related row (option orders/trades, the `Options` position
    section, and option TRD rows in `Cash Balance`) is kept byte-verbatim
    in every field that P&L golden tests depend on: AMOUNT, Commissions &
    Fees, descriptions, OSI/OPRA codes. The one exception is the running
    `BALANCE` column in `Cash Balance`, which is always recomputed (see
    below), so it is not byte-identical even on an all-options day.
  - Everything else is anonymised: equity/ETF ticker symbols become
    `DUMMY`, dollar amounts are rescaled by a fixed factor, and the
    Equities / Profits and Losses position sections are collapsed to a
    single plausible dummy row (Futures/Forex/Crypto sections carry no
    data rows in the source and are copied through - the script refuses
    to run if a future source statement puts a real dollar figure there).
    Account Summary (net-liq, buying power, YTD fees) is rescaled the same
    way.
  - The `Cash Balance` running `BALANCE` column is recomputed from a fake
    opening balance (a fixed baseline plus the real opening balance
    rescaled, so there's always headroom for a same-day option trade,
    which keeps its real, unscaled dollar size) plus each row's *emitted*
    amount: the real amount for option rows, the rescaled amount for
    non-option rows. It stays internally self-consistent even though it
    mixes real and rescaled figures.

Never copy `~/workspace/example_trades` here un-anonymised - re-run the
script instead:

    python3 scripts/anonymize_statements.py

The script itself fails closed: any statement row it does not recognise
aborts the run, and the whole output is built in a temporary directory,
swept for the real account id, and only then copied here - so a failure
leaves this directory untouched rather than half-written.

The "replaced everywhere" promise is also enforced from the outside, by two
independent repo-wide guards:

- `crates/wingspan-core/tests/redaction.rs` fails the build if any file in
  the repository - fixture, source, doc or comment - carries a statement
  header whose account id is not `00000000TEST`.
- `scripts/check_redaction.py` (run by `just redaction-guard` and by CI)
  is not tied to that header phrase: it flags the account id's *shape*
  (8 digits immediately followed by a broker/account code) anywhere in any
  file, and likewise the shape of a real execution ref (13 digits starting
  `100`, which no synthetic ref shares).
